Node dependency installs. Apply only when the project contains package.json. Detect the manager from the packageManager field, otherwise from pnpm-lock.yaml, yarn.lock, or package-lock.json. If none of those identify it, ask before installing.  Direct dependencies the agent adds or upgrades are exact versions, with no ^ or ~. Keep the lockfile committed. Keeping the lockfile in git does not mean committing it. A commit still happens only when asked. Reproduce installs with npm ci, pnpm install --frozen-lockfile, or yarn's immutable install. Convert existing ranges only when the user asks to install, update, or secure dependencies, pinning each one to the version already in the lockfile.  Before a new or upgraded package is extracted or its scripts run: copy package.json and the lockfile, update the lockfile only, audit at high severity, and restore both files if the audit fails. Require a release age of 7 days: npm uses --before, pnpm sets minimumReleaseAge to 10080, Yarn Berry sets npmMinimalAgeGate to "1w". Yarn 1 has no age gate; the backup, exact pin, disabled scripts, and audit still apply. Read the installed pnpm major version: pnpm 11 stores saveExact, minimumReleaseAge, and allowBuilds in pnpm-workspace.yaml; earlier pnpm stores them in .npmrc.  Dependency lifecycle scripts stay off until that package's script is reviewed and explicitly allowed: npm ignore-scripts, pnpm allowBuilds or onlyBuiltDependencies, Yarn Berry enableScripts false plus dependenciesMeta, Yarn 1 ignore-scripts. Save-exact is the default for later adds: npm and older pnpm save-exact, pnpm 11 saveExact, Yarn Berry defaultSemverRangePrefix "", Yarn 1 save-prefix "".
